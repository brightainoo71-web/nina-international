# Academic Demonstration Script for Lecturers & Examiners

## Nina International Secure School Management System
**Topic**: Enterprise Cryptographic Implementations, Role-Based Access Control, and Resilient Disaster Recovery Architecture

---

### Step 1: Introduction (1 Minute)
> *"Good morning/afternoon, Sir/Madam. Today I am presenting **Nina International**, a full-stack, secure School Management System built using React, React Native (Expo Go), Node.js with TypeScript, and Cloud Firestore. The primary objective of this project is to demonstrate real-world computer and information security principles through functioning, verifiable code rather than superficial UI templates."*

---

### Step 2: The Password Salt & Pepper Mechanism (3 Minutes)
1. Navigate to the login page on the web app (`http://localhost:5173`).
2. Log in as Administrator using `admin@ninainternational.edu` (Click the quick-fill button, then authenticate via 2FA).
3. Navigate to **Credential Audit** in the top navigation.
4. **Explain to the lecturer**:
   > *"A central academic requirement of this project was demonstrating custom password hashing using Argon2id with unique salts and a server-side pepper. On this Credential Security Audit page, you can see real accounts registered in the database."*
   - Point out the **Algorithm** (`Argon2id v19`).
   - Point out the **Memory hardness parameter**: $65,536\text{ KiB}$ (64 MB of RAM per hash), 3 iterations, 4 parallelism threads. This defeats mass GPU cracking.
   - Point out the **Unique 128-bit Salt**: Notice that each account has a different hex salt generated by `crypto.randomBytes(16)`. Even if two students pick the exact same password, their stored hashes will look completely different, neutralizing Rainbow Table attacks.
   - Point out the **Server-Side Pepper**: The pepper is **not stored beside the hash in the database**. It is maintained in AWS Secrets Manager / server environment.
5. **Interactive Demonstration**:
   - Scroll down to the **Controlled Academic Demonstration: Live Transformation Pipeline**.
   - Ask the lecturer for any sample word or type `LecturerVerification2026!`.
   - Click **Run Transformation Pipeline**.
   - Show the live four-stage breakdown:
     - **Stage 1**: Plaintext Input.
     - **Stage 2**: Keyed HMAC-SHA256 transformation using the server pepper secret.
     - **Stage 3**: Unique 128-bit random salt generation.
     - **Stage 4**: Encoded Argon2id hash.
   - Clarify: *"Notice that the actual secret contents of the pepper are never disclosed to the client; only the key identifier is confirmed."*

### Step 3: Two-Factor Authentication (2 Minutes)
1. Show the **Student Dashboard** or **Administrator Security**.
2. Log out and demonstrate the login flow:
   - When entering valid credentials, the system blocks direct session generation and responds with a scoped `twoFactorToken`.
   - Show the two distinct second-factor options: **Google Authenticator-compatible TOTP** (RFC 6238) and **Email Verification OTP**.
   - Explain: *"TOTP secrets are encrypted at rest using AES-256-GCM authenticated encryption. Furthermore, 8 single-use recovery codes are issued, and only their SHA-256 hashes are stored in the database."*

---

### Step 4: Role-Based Access Control & IDOR Prevention (2 Minutes)
1. Log in as **Student** (`student.kofi@ninainternational.edu`).
   - Show that the student can only view their own student digital badge, their timetable, and their own assessment scores.
   - Explain: *"If a student modifies an API request or URL parameter to query another student's document ID, the backend `requireStudentSelfOrStaff` middleware and Firestore Security Rules compare `request.auth.uid == userId` and instantly abort the request with 403 Forbidden."*
2. Log in as **Teacher** (`teacher.mensah@ninainternational.edu`).
   - Show that teachers can record attendance and modify assessment scores.
   - **Demonstrate Grade Auditability**:
     - Change a student's grade from 92 to 95.
     - Note the mandatory input for **Reason for change**.
     - Commit the grade and scroll to the **Immutable Grade Modification History** table, showing the instructor's name, previous score, new score, and reason timestamped in the audit log.

---

### Step 5: Soft Deletion & Account Governance (2 Minutes)
1. Log back in as **Administrator**.
2. Open **User Management**.
3. Locate a student account and click **Deactivate** (Soft-delete).
4. Enter an administrative reason (e.g. `Administrative disciplinary suspension`).
5. Open an incognito browser window and attempt to log in with that deactivated student account.
6. Show that the login is immediately rejected: *"This account has been deactivated. Please contact the administrator."*
7. Return to the Administrator portal, click **Restore**, and demonstrate that the account is reactivated without losing any academic history.

---

### Step 6: Configuration Restore Points vs Disaster Recovery (2 Minutes)
1. Open **Restore Points** in the Administrator portal.
   - Explain: *"Configuration snapshots capture system policy without touching school records."*
   - Show the **Preview Diff** feature before restoration.
   - Point out that restoring a snapshot automatically takes a rollback snapshot and preserves student grades untouched.
2. Open **Disaster Recovery**.
   - Show the backup table: archives are encrypted using **AES-256-GCM** with a **SHA-256** checksum.
   - Click **Test Integrity** on a backup to show that the system decrypts, re-computes checksums, and tallies records in memory.
   - Point to the AWS S3 integration card and explain that archives are staged for transfer to the client-owned Amazon S3 bucket.

2. Open the **Expo Go** app on an Android device or emulator.
3. Show that the student, teacher, staff, and admin views load cleanly on mobile with token storage backed by `expo-secure-store`.
